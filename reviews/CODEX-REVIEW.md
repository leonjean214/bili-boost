# bili-boost v1.2.0 复核

## 已修改

- 给两处 `MediaCapabilities.decodingInfo()` 增加 3 秒超时。AV1 探测超时或异常后保持 `null`，HUD 从“探测中”恢复为“未知”，`重新探测AV1()` 也会按时返回。
- 给 AV1 探测增加单次复用和代次校验。手动重探会使旧探测失效，较晚返回的旧 promise 不会覆盖新结果；缓存只接受严格的布尔值。
- 保留三态和兼容行为：`auto` 未知时仍剔除 AV1，既有 `bhw_codec=true/false` 仍分别表示强制开/关。自动探测只在视频页执行，减少首页和无关 iframe 的重复查询。
- 修正 CDN 测速计时：从请求发起开始计时，避免把首个数据块计入流量却不计下载时间造成严重高估。
- 修正 CDN 切源闭环：测速完成前使用的会话赢家现在会登记为当前源；卡顿期间新加入的拒绝源不会被异步测速结果重新选中；黑名单或拒绝名单中的缓存源会清除并重新测速。
- 修正网络 hook：支持 `URL` 对象形式的 `fetch` 和 `XHR.open`；XHR 复用时会清理上一请求的 playurl getter 和 CDN 状态；`loadend` 监听改为单次并捕获本次请求的 host，避免重复或串记。
- 版本保持 `1.2.0`，文件头和 `SCRIPT_VERSION` 一致；未引入依赖、网络请求或动态代码执行。

## 验证

- `node --check bili-boost.user.js`、`git diff --check`、版本一致性检查通过。
- 定向模拟通过：`decodingInfo()` 永久 pending 时约 3 秒返回未知且缓存保持 `null`；手动重探竞态不会被旧结果覆盖；旧版布尔配置、`URL` 输入和 XHR 复用均通过。
- `node tools/qa-boost.mjs`：脚本相关项目 8 项通过、2 项因未登录跳过；唯一失败是未注入脚本的对照组当天由 B 站选择了 AVC，而测试固定期待 AV1，与本次修改无关。

## 发现但未修改

- 真实分片速度目前只统计 XHR；如果播放器改用 `fetch` 拉分片，HUD 的“实测速度”会为空。安全统计 fetch 流需要包装响应流，兼容风险较高。
- `waiting` / `stalled` 也可能由主动拖动、切清晰度或初始缓冲触发，现有逻辑可能把它们当成 CDN 卡顿；缺少播放器上下文时无法可靠区分。
- `bhw_av1hw` 没有自动过期。浏览器、系统或驱动升级后能力结果可能陈旧，目前需调用 `重新探测AV1()` 主动刷新。
- fetch playurl 改写通过新建 `Response` 返回，标准只读元数据（如 `url`、`redirected`、`type`）无法完整保留；现有播放器和回归测试未依赖这些字段。
